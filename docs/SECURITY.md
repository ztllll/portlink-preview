# 安全边界

- SSH服务器必须可信并允许TCP forwarding。首连显示SHA256指纹，用户应通过服务器控制台或管理员等另一可信渠道核验；仅点击接受仍只是TOFU，不等于已获外部身份验证。
- 按主机+SSH端口保存一个算法/指纹。指纹或算法变化硬阻断；正常首次信任窗口不能覆盖已有pin。合法换钥时先通过独立渠道核实，再备份并人工修改信任记录。本版故意没有一键忽略主机验证。信任文件损坏时fail closed，不自动用可能过期的备份降级。
- Mac使用系统登录Keychain，不启用跨应用共享或依赖Keychain Sharing provisioning。旧Data Protection Keychain预览数据需重新保存密码，不做未经确认的隐式迁移。
- 密码只保存到OS安全存储。普通配置、备份不包含密码。不会启用SSH debug/trace；生产错误不展示原始异常。不要把真实密码提交到源码、截图或测试fixture。
- 转发规则的本地监听地址默认且推荐为 127.0.0.1。允许用户把某条规则改为其他本机 IPv4 地址（含 0.0.0.0），此时同一网络中的其他设备也可能访问该转发而无需 SSH 凭据；界面会在编辑和连接面板中明确警告，仅在确有需要时使用。本地端口限制在 1024–65535，不请求管理员权限。loopback不等于应用私有隔离：同设备其他有网络能力的进程/应用可能访问该端口。远端服务自己的认证/TLS仍应启用。
- 加密覆盖当前设备至SSH服务器段；每条规则的目标默认是SSH服务器自身 127.0.0.1，也可由用户指定服务器能访问的其他地址，该地址由服务器解析，服务器到该目标的一段不受 PortLink 加密保护。浏览器到本地监听段为普通TCP；打开HTTP只适用于目标实际提供HTTP服务。
- 支持SSH password认证；需要OTP/MFA、硬件密钥、私钥或keyboard-interactive的服务器不在首版保证范围，不能通过关闭服务端安全策略来迁就客户端。
- 全局单服务器连接（该服务器的全部规则共用一条SSH会话），每次连接最多128个并发转发socket，每台服务器最多32条规则；超时和关闭有界。网络故障持续按上限30秒的退避策略重试；认证/主机信任失败停止；所有规则的本地端口都无法绑定时停止，部分规则无法绑定时仅该条失败，不影响其余规则，也不会终止占用该端口的进程。
- 文件原子写保护意外中断，不是防同用户恶意篡改的加密防线；本地同用户恶意程序或管理员可能读取进程内存/破坏信任库。
- 系统凭据库锁定、权限拒绝、密码过期、应用数据清除会使自动连接不可用，不做明文降级。
- Android为用户发起的按需会话：无开机自启、无自动复活、无电池豁免或保活绕过；系统强杀/Doze可导致停止。
- 公开发行前必须完成依赖漏洞复查、平台凭据实测、签名及真实服务器互通验收。
